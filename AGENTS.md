# Инструкции для работы с CMakeBuild

Перед изменениями читать этот файл и README.md.

## Код и интерфейс

- Использовать современный C++23. Для кода с Qt использовать Qt 6.11 или новее.
- Интерфейс панели использует закреплённый снимок FLTK 1.5.0-dev (`b8ccd16`, исправления Windows DPI) и не требует Qt; сохранять её самостоятельную поставку одним EXE со статической FLTK. Windows-операции держать в платформенном модуле, существующий движок сборки и запуска использует Win32 API. Точный commit и SHA256 зависимости находятся в `cmake/fltk.cmake`; не использовать плавающую ветку.
- Для оформления Qt Widgets не использовать QSS без явного запроса пользователя. Предпочитать постоянный QProxyStyle, QPalette, QPainter и делегаты. При смене темы обновлять палитру и цвета отрисовки, сохраняя стиль, шрифты и геометрию; избегать массовых unpolish/polish и лишних обновлений моделей и редакторов.

## Постоянное место сборки

- Готовая программа всегда находится в `C:\GitRepos\CmakeBuild\CMakeBuild.exe`. Не создавать новые папки для готовых версий и не оставлять результат только в промежуточной папке.
- Обычная сборка: `powershell -ExecutionPolicy Bypass -File .\build.ps1 -Toolchain MSVC -Configuration Release` из корня проекта. Скрипт поддерживает также MinGW и Debug с тем же конечным путём.
- Кэши и внутренние файлы компиляторов хранить в существующих `build\msvc`, `build\mingw-release`, `build\mingw-debug`; тесты — в `build\engine-tests`.
- Если сборка выполняется через CMake напрямую, использовать пресеты. Для сборки конкретной цели использовать `CMakeBuildPublish`, чтобы корневой EXE обновился даже при переключении на уже собранную конфигурацию.
- Не запускать несколько сборок панели одновременно: они обновляют один конечный EXE.

## Версии

- Единственный источник версии — файл `VERSION` в формате `MAJOR.MINOR.PATCH`. Заголовок программы, свойства EXE и манифест генерируются из него средствами CMake.
- После законченного изменения программы повышать PATCH для исправлений, MINOR для новых совместимых возможностей, MAJOR для несовместимых изменений. Вносить запись в CHANGELOG.md. Для повторной сборки тех же исходников версию не повышать.
- При изменении версии пересобрать программу по постоянному пути и проверить FileVersion/ProductVersion готового EXE.

## Порядок работы

- Перед тестами, которые временно меняют настройки панели, сохранять исходный `settings.ini`. После тестов обязательно возвращать предыдущие настройки, в том числе при ошибке или прерывании проверки. Проверять восстановление; не оставлять пользователю тестовый проект, каталог сборки или другие временные параметры.
- Сначала завершать связанные изменения, затем выполнять общую сборку и необходимые проверки. Не собирать и не тестировать после каждой мелочи.
- Во время долгой работы давать пользователю краткий комментарий не реже чем каждые 30 секунд.
