# Результат FLTK vs Nana — 2026-10-06

Актуальная серия после оптимизации Nana 1.8.5:
[NANA-OPTIMIZATION.md](NANA-OPTIMIZATION.md). Суммарная обработка журнала стала
быстрее FLTK; память и p95 пакета остаются ниже у FLTK.

## Исходная серия для Nana 1.8.4, до оптимизации

В исходной серии CMakeBuild **FLTK была предпочтительнее по работе с журналом,
памяти и CPU в простое**. Nana быстрее полностью перерисовывала уже заполненное
окно. Ниже сохранены исходные измерения; они не определяют победителя для любых
приложений.

FLTK-панель **1.8.3**, Nana-панель **1.8.4**; MSVC 1944, Release x64,
статические зависимости. Машина: Windows 11 Pro build 26200, Intel Core i7-11700,
8 ядер / 16 потоков, около 32 GiB RAM. Масштаб 125% (120 DPI), окно 775×456
физических пикселей, 620×365 логических. По семь независимых процессов каждой
версии, один предварительный прогрев. Порядок пар FLTK/Nana и Nana/FLTK
чередовался. В таблице — медианы по процессам; меньшее значение лучше.

| Метрика | FLTK | Nana | Nana / FLTK |
| --- | ---: | ---: | ---: |
| Вход в harness → первая нативная отрисовка, мс | 64,40 | 90,26 | 1,40× |
| Запуск процесса → сигнал о первой отрисовке, мс | 154,21 | 169,16 | 1,10× |
| Private Bytes в простое, MiB | 2,45 | 5,68 | 2,32× |
| Working Set в простое, MiB | 14,36 | 17,10 | 1,19× |
| CPU в простое, мс/с | 0,00 | 20,75 | — |
| 8192 строки журнала / 128 пакетов, мс | 1258,77 | 16274,42 | 12,93× |
| Обработка пакета журнала p95, мс | 11,15 | 201,93 | 18,12× |
| Private Bytes после журнала, MiB | 8,96 | 16,50 | 1,84× |
| Полная перерисовка заполненного окна p50, мс | 8,37 | 3,49 | 0,42× |
| Смена палитры и обработка событий p50, мс | 8,45 | 9,55 | 1,13× |
| Смена палитры и обработка событий p95, мс | 9,93 | 18,16 | 1,83× |

В стрессе журнала FLTK быстрее в **12,9 раза**.
Пауза p95 пакета у Nana — около 202 мс против 11 мс у FLTK.
Nana быстрее по медиане полной перерисовки в **2,4 раза**.

Нагрузка: 8192 строки, 1 473 450 байт UTF-8, 128 пакетов по 64 строки,
кириллица и emoji. Обе реализации сохранили одинаковый остаток 553 500 байт
после обрезки старого вывода. Проверены текст настоящего виджета, геометрия
и DPI после всех операций. Бенч рисует каждый пакет, обходя очереди движка.
Реальный вывод CMake объединяется перед обновлением UI, поэтому это **стресс
интерфейса журнала**, а не замер времени сборки проекта.

CPU FLTK в простое был ниже чувствительности короткого измерения во всех
процессах. У Nana медиана 20,75 мс/с — примерно
2,1% одного ядра; диапазон от
10,36 до 103,26 мс/с.
Нулевой результат FLTK не означает буквально нулевой расход. Память относится
к процессам бенчмарков; после нагрузки она включает общие входные буферы.

В исходниках есть вероятные причины различий: Nana каждые 65 мс безусловно
обновляет панель, а добавление текста без переноса строк запускает пересчёт
ширины накопленных строк. Дополнительно копируется прошлое содержимое журнала.
Соответствующие пути находятся в [nana/src/ui.cpp](../nana/src/ui.cpp)
и редакторе закреплённой зависимости NanaPlus. Это объяснение по путям кода;
доли расходов профилировщиком не измерялись. Полная перерисовка и добавление
новых строк используют разные пути.

Запуск измерен у инструментированных harness EXE с открытым журналом и отдельным
INI, без пользовательского проекта. Отрисовка завершается на уровне toolkit/GDI,
без ожидания показа кадра DWM. Кэш ОС прогрет. Подробнее — [методика](README.md).
