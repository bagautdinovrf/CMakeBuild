# Проверки варианта Nana

Проверки используют отдельные временные проекты и UTF-16 INI. Пользовательский
`%LOCALAPPDATA%\CMakeBuild\settings.ini` не читается и не меняется. Исполняемые
фикстуры и их дочерние процессы принадлежат тестам; существующие приложения
не останавливаются.

Из папки `nana`, после завершения связанных изменений:

```powershell
cmake --preset msvc-tests
cmake --build --preset msvc-tests-release --parallel
ctest --test-dir build/engine-tests -C Release --output-on-failure
```

`nana_controller` проверяет настоящий движок и контроллер: восстановление
CMake File API и выбранной цели, профили проектов и историю, параметры запуска,
сборку и действия меню, очередь запуска, отмену и завершение деревьев процессов,
Unicode, длительность, прогресс и ограничение журнала. Для реальных сборок нужен
установленный MSVC и CMake; интерфейс Nana и Qt тесту контроллера не требуются.

Первая успешная сборка создаёт две настоящие цели C++ без прежних EXE. Выбор
цели после команды «Собрать и запустить» должен запускать её ровно один раз.
Дочерний процесс подтверждает сохранённые аргументы, окружение и рабочую папку
относительно проекта. Пересборка сохраняет обычную цель сборки; очистка и
отдельный CMake не принимают очередь запуска. Ошибка компиляции с прежним EXE
не запускает его, а последующая обычная сборка не наследует запрос запуска.

`nana_ui` использует настоящие виджеты Nana. Он проверяет callbacks, журнал,
сохранение выделения и положения просмотра, палитры, геометрию и модальные
настройки. Растровые снимки сохраняются в `build/engine-tests/tests/ui-smoke/images`.
Счётчики реальных callback отрисовки также проверяют, что неизменившаяся панель
не перерисовывается в простое и при добавлении только текста журнала.
Проверку можно запустить отдельно после общей сборки:

```powershell
.\build\engine-tests\tests\Release\NanaUiSmoke.exe .\build\engine-tests\tests\ui-smoke
```

Автотесты не заменяют
проверку Win32 диалогов выбора файлов и переноса окна между физическими
мониторами с разным DPI.

`nana_editor` сравнивает два настоящих текстовых виджета: один получает
последовательные изменения, второй заново восстанавливается из полного текста.
Проверяются Unicode, вставка в середину, удаление, undo/redo, количество строк,
пределы прокрутки и пиксели области текста, изменение размера, метрик шрифта
и режима переноса строк. Отдельный сценарий сохраняет выделение, caret и
viewport при добавлении сообщений, как в журнале панели.

`nana_dpi` отправляет настоящие `WM_DPICHANGED` в HWND панели для повторных
переходов 96/120/144/192 DPI. Проверяются размеры Win32 и Nana, предложенное
положение, логические размеры INI, виджеты, нативные шрифты, выделение и фокус,
callback кнопки и нативный `WM_SIZE`. Отдельная скрытая панель перемещается
между доступными физическими мониторами; тест сообщает их число и фактический
DPI. Все окна принадлежат тесту, не активируются, а INI находятся только в
`build/engine-tests/tests/dpi-tests`. Растровая матрица масштабов остаётся в
`NanaUiSmoke --render-preview`.

Native drag-проверка удерживает заголовок при смене DPI и отпускает кнопку над
виджетами сборки и журнала. Проверяются оба capture, потерянный mouse-up,
`WM_CANCELMODE`, передача capture другому тестовому HWND и следующий drag.
Она не перемещает физический курсор, не меняет состояние кнопок пользователя
и не активирует окна; после завершения drag дальнейшие mouse-move не двигают
тестовую панель.

Дополнительно проверяются 48 переходов с сохранением исходной точки захвата
в логических координатах и первое движение при неизменившемся указателе.
Для native drag окно теста полностью прозрачно, пропускает мышь и не
активируется: это позволяет использовать реальную экранную точку сообщения
с обычным смещением заголовка, не двигая физический курсор. Точка захвата
настроек проверяется также при ограничении размеров рабочего пространства.

## Визуальное соответствие основной панели

Эталон — фактическая отрисовка основной FLTK-панели, создаваемая
`build/engine-tests/Release/journal_ui.exe --render-preview build/engine-tests/ui-preview`
из корня проекта. Заголовок эталона должен содержать текущую версию 1.8.3.
Старые одиночные PNG не заменяют свежие PPM эталона.

Сравнение требует собственного рендера Nana для каждого масштаба 100/125/150/200%.
Меняются размеры виджетов, шрифты и координаты отрисовки; увеличение уже готового
bitmap не проверяет DPI. Панель использует изолированный INI, и тест не меняет
Windows DPI или пользовательские настройки. Входные данные для сравнимых кадров
заданы в `visual_fixture.hpp`: путь демонстрационного проекта, Release,
build-release, ExampleApp/ExampleTool, одинаковый журнал.

Для каждого масштаба и обеих тем нужны 32 сравнимых кадра:

| Вид | Логический размер | Имена файлов |
| --- | --- | --- |
| Компактная панель | 500×150 | panel-light-100.bmp … panel-dark-200.bmp |
| Hover, нажатие, focus, disabled | 500×150 | panel-light-states-100.bmp … panel-dark-states-200.bmp |
| Панель с журналом | 500×365 | panel-light-journal-100.bmp … panel-dark-journal-200.bmp |
| Настройки | 505×660 | settings-light-100.bmp … settings-dark-200.bmp |

Отдельная команда сохраняет эту матрицу в `build/engine-tests/tests/ui-preview`,
не смешивая её с кадрами функционального smoke:

```powershell
.\build\engine-tests\tests\Release\NanaUiSmoke.exe --render-preview .\build\engine-tests\tests\ui-preview
```

Фактические размеры эталонных кадров при 100/125/150/200%: компактная панель
500×150 / 625×187 / 750×225 / 1000×300, панель с журналом
500×365 / 625×456 / 750×547 / 1000×730, настройки
505×660 / 631×825 / 757×990 / 1010×1320. Размер окна усечён до целого.
Для прямоугольников FLTK отдельно усекает обе координаты границ:
left=floor(x×scale), right=floor((x+w)×scale), затем width=right−left;
аналогично для высоты. Округление через lround или отдельное масштабирование
ширины даёт видимое смещение на дробных масштабах. Логические ширины кнопок
вычисляются по шрифту 96 DPI и затем масштабируются вместе с остальной панелью.

В кадре states шестерёнка имеет hover, кнопка сборки нажата, обе части запуска
disabled, а Close имеет focus. Это тот же набор состояний, который рисует FLTK.
В дополнение нужен кадр «Ожидание»: недоступная основная кнопка с этой подписью,
без изменения размеров запуска, строка «Запуск после сборки» и активный прогресс.
Нужно также просмотреть подписи «Запустить»/«Остановить» и подсказки; выбранный
Pin/Log меняет фон и цвет, сохраняя положение и размер.

Критерии принятия панели в логических пикселях:

| Элемент | Геометрия FLTK |
| --- | --- |
| Минимальная ширина / компактная высота / минимальная высота журнала | 500 / 150 / 240 |
| Close / Minimize / Log / Settings | x=W−40/W−71/W−103/W−135; y=9; 27×27 |
| Pin | x=W−143−pinWidth; y=9; pinWidth×27; иконка и текст |
| Выбор проекта / стрелка | (15,57,36,37) / (51,57,23,37); иконка файла |
| Run / его стрелка | (W−43−runWidth,57,runWidth,37) / (W−43,57,28,37) |
| Build / его стрелка | (RunX−36−buildWidth,57,buildWidth,37) / (BuildX+buildWidth,57,28,37) |
| Логотип | три квадрата 5×5 в (16,23), (23,16), (23,23) |
| Заголовок | x=39; y=9; h=28; суффикс «· Nana» у варианта Nana |
| Имя проекта / полный путь | x=84; y=55/77; h=21; доступная ширина BuildX−94 |
| Разделитель состояния / точка | y=113 / (16,128,6,6) |
| Текст состояния | x=30; y=116; h=31; длительность выравнивается справа |
| Прогресс | x=15; y=104; w=W−30; h=5 |
| Журнал | (15,153,W−30,H−171); разделитель y=151 |

Ширины кнопок измеряются по всем возможным подписям заранее и не меняются при
переключении состояния: pinWidth=max(109,ceil(max text width)+38),
buildWidth=max(96,ceil(max width «Собрать»/«Отменить»)+38),
runWidth=max(107,ceil(max width «Запустить»/«Остановить»/«Ожидание»)+38).
В FLTK Segoe UI имеет высоту 13 логических пикселей для основных подписей и 12
для Pin, статуса и пути; журнал — Consolas 12. Для Nana, задающего размер в
пунктах, это 9.75/9 pt при 96 DPI. Размеры масштабируются один раз.

Кнопки имеют радиус 4 и контур толщиной 1; разделённые кнопки образуют один
внешний контур. Run заполняется accent и имеет иконку треугольника/остановки,
Build — контур гаечного ключа/отмены. Заголовок содержит отдельные нарисованные
иконки Pin, шестерёнки, журнала, сворачивания и закрытия. Кнопки «Очистить» и
«Копировать» над журналом отсутствуют.
Декоративные символы шрифта и стандартные рамки Nana не заменяют эталонные иконки.

Все три меню разделённых кнопок используют Segoe UI 13 px, высоту строки
по метрикам этого шрифта плюс 4 px (FLTK menu_linespacing), фон Surface и
активную строку Accent с контрастным текстом. Выбранная цель запуска отмечается
кружком радио-кнопки; текущий проект — квадратом с галочкой. Меню проектов
начинается с «Открыть проект…» и правой подписи Ctrl+O, затем разделитель и MRU.
В меню сборки справа отображаются F6 и F5 для соответствующих команд.
Меню открывается у левой границы основной части кнопки, сразу под её нижней
границей; перенос над кнопкой допускается только при нехватке рабочей области.

Исходный FLTK-журнал использует стандартное меню Fl_Text_Display с Cut/Copy/Paste;
Cut и Paste недоступны в режиме readonly. Этот popup использует стандартный
FL_HELVETICA (Microsoft Sans Serif на Windows) размером 14 px. Расширенные пункты
Nana для очистки/переноса/автопрокрутки в режиме соответствия «1 в 1» отсутствуют.

Палитра должна совпадать по RGB:

| Цвет | Светлая тема | Тёмная тема |
| --- | --- | --- |
| Surface | 255,255,255 | 32,35,41 |
| Soft | 244,246,248 | 43,48,56 |
| Text | 36,41,51 | 238,241,245 |
| Muted | 104,115,130 | 169,180,195 |
| Line | 223,228,235 | 60,67,78 |
| Accent | 18,101,211 | 118,173,255 |
| Accent text | 255,255,255 | 20,36,61 |
| Success | 34,123,83 | 116,214,163 |
| Error | 182,49,54 | 255,149,149 |
| Scroll track | 244,246,249 | 43,49,57 |
| Scroll thumb | 218,225,236 | 62,72,84 |

Основной фон окна — Surface. Hover и выбранные Pin/Log используют Soft;
disabled-текст смешивает Muted 68% и Surface 32%. Нажатие смешивает текущий фон
86% и Text 14%; hover основной кнопки запуска — её фон 94% и Text 6%.
Палитра меняется без изменения шрифта, геометрии, выделения и прокрутки.

Для необязательного сравнения изображений скриптом `visual_parity.py` нужны
Python 3 и библиотека Pillow (`python -m pip install Pillow`). Для сборки
программы и проверок CTest эти зависимости не требуются.

`visual_parity.py` сравнивает непосредственно свежие BMP/PNG/PPM, без изменения
их размеров. Он проверяет размеры кадров, фон, логотип, контур основной кнопки
и разделитель, а также сообщает полную RMS-разницу и долю одинаковых пикселей
для визуальной оценки отличий шрифтов и содержимого. Отсутствующий кадр или
структурное расхождение даёт ненулевой код выхода; отчёт не доказывает равенство
всех деталей и не заменяет просмотр каждой пары.

```powershell
python tests/visual_parity.py --manifest
python tests/visual_parity.py --report build/engine-tests/tests/ui-preview/visual-parity.json
```
