# CMakeBuild

Небольшая горизонтальная панель для сборки и запуска CMake-проектов в Windows 10/11 x64. Интерфейс написан на C++23 и закреплённом снимке FLTK 1.5.0-dev: панель, настройки, меню целей и журнал используют FLTK. Qt и его DLL для самой панели не нужны.

Движок сборки и запуска остаётся на Win32: он управляет деревьями процессов через Job Objects, ищет инструменты и читает CMake File API. Системная тема, закрепление окна, геометрия Windows, преобразования Unicode и совместимое хранилище INI вынесены в платформенный модуль. Интерфейс отделён от него для дальнейшего переноса; Linux и macOS на этом этапе не поддерживаются.

Готовая Release-версия находится в `C:\GitRepos\CmakeBuild\CMakeBuild.exe`. Для переноса панели достаточно этого одного файла. CMake и компилятор устанавливаются отдельно и используются для сборки выбранных проектов.

EXE и окно на панели задач используют собственную синюю иконку с тремя блоками и стрелкой запуска. Она встроена в программу в размерах 16–256 пикселей.

## Вариант интерфейса Nana

Помимо основной панели FLTK доступен самостоятельный вариант с тем же набором команд сборки и запуска:

- [Nana](nana/README.md): библиотека из [форка NanaPlus](https://github.com/bagautdinovrf/nanaplus/tree/main) на основе `develop-1.8`, готовая программа `nana\CMakeBuild.exe`. Исходники библиотеки закреплены точным commit и SHA256.

Вариант Nana имеет собственные исходники, сборочный скрипт и пресеты; его сборка обновляет EXE только в своей папке. Обе панели имеют общую версию из корневого `VERSION` и используют совместимый `%LOCALAPPDATA%\CMakeBuild\settings.ini`: профили проектов, недавние проекты и параметры каждой цели запуска доступны при переходе между интерфейсами. Для последовательной работы закрывайте предыдущую панель, чтобы её последняя запись настроек не перекрыла более новые изменения.

Сравнить производительность настоящих панелей FLTK и Nana можно командой `powershell -ExecutionPolicy Bypass -File .\benchmarks\run.ps1`. Бенчи измеряют запуск, память и CPU в простое, обработку большого журнала, перерисовку и смену палитры; создают отчёты JSON/CSV/Markdown и используют отдельные INI. Методика и ограничения описаны в [benchmarks/README.md](benchmarks/README.md).
Результаты исправления медленного журнала и постоянной перерисовки Nana 1.8.5 —
в [отчёте об оптимизации](benchmarks/NANA-OPTIMIZATION.md).
Проверка используемых виджетов и доработки NanaPlus 1.9.3 описаны
в [отчёте по виджетам](benchmarks/NANA-WIDGET-OPTIMIZATION.md).

## Версия программы

Текущая общая версия FLTK и Nana — **1.10.0**. Она отображается в заголовках панелей и на вкладке **Подробно** в свойствах обоих `CMakeBuild.exe`. Заголовки панелей: **CMakeBuild 1.10.0 · FLTK** и **CMakeBuild 1.10.0 · Nana**.

Единственный источник версии обеих панелей — корневой файл `VERSION` в формате `MAJOR.MINOR.PATCH`; Nana читает этот же файл через `../VERSION`. CMake автоматически подставляет его в заголовки программ, FileVersion/ProductVersion обоих EXE и манифесты Windows. Для исправлений повышается PATCH, для совместимых новых возможностей — MINOR, для несовместимых изменений — MAJOR. При изменении версии последовательно пересобираются оба варианта. Повторная сборка тех же исходников сохраняет версию. История изменений находится в `CHANGELOG.md` и `nana/CHANGELOG.md`, правила для дальнейшей работы — в `AGENTS.md`.

## Использование

1. Запустите `CMakeBuild.exe`.
2. Выберите `CMakeLists.txt` нужного проекта.
3. При необходимости откройте настройки и укажите каталог сборки, конфигурацию, CMake, компилятор, цель сборки и цель запуска.
4. Нажмите **Собрать**. При первой сборке панель подготовит каталог через CMake, затем соберёт проект. Повторная сборка использует готовую конфигурацию; вывод процессов появится в журнале. После завершения справа в строке состояния и в журнале отображается время сборки, включая подготовку окружения и конфигурацию CMake, если она потребовалась. Время выводится также при ошибке и отмене.
5. Нажмите стрелку справа на кнопке **Запустить** и выберите один из собранных EXE проекта. Основная часть кнопки запускает выбранное приложение. Выбор запоминается отдельно для каждого проекта, в том числе после перезапуска панели.

Панель можно закрепить поверх остальных окон и переместить в удобное место. Сборка выполняется в рабочем потоке, поэтому окно остаётся доступным во время работы CMake.

Стрелка рядом с выбором проекта открывает десять недавних проектов и команду «Открыть проект…». История сохраняется после перезапуска; разные записи одного Windows-пути объединяются. При переключении восстанавливается полный набор настроек проекта: CMake, компилятор, конфигурация, каталог сборки, цель сборки, включение тестов и цель запуска. Недоступные проекты остаются в истории; попытка открыть удалённый файл сообщает об ошибке и сохраняет текущий проект. Для нового проекта используются Release, автоматический компилятор и сборка без тестов; путь CMake может наследоваться. Прежние настройки INI продолжают читаться.

В настройках выбранной цели запуска доступны аргументы, рабочая папка и окружение. Аргументы передаются непосредственно программе по правилам командной строки Windows; пути с пробелами заключайте в двойные кавычки. Пустая рабочая папка означает каталог EXE, относительный путь отсчитывается от папки проекта. Переменные вводятся по одной строке в формате `ИМЯ=значение`; пустое значение допустимо, имена сравниваются без учёта регистра. Пользовательский `PATH` заменяет автоматически подготовленный PATH. Изменения применяются только к запускаемому процессу. Каждая цель каждого проекта имеет собственные параметры; переключение цели внутри диалога сохраняет черновики, «Отмена» их отбрасывает, «Сохранить» записывает.

Первые два пункта меню сборки задают режим основной кнопки и сразу выполняют выбранное действие. В режиме **Собрать** кнопка имеет цвет `#bcc5ab`, в режиме **Собрать и запустить** — `#c4ffd2`; её подпись соответствует режиму. Следующие нажатия повторяют выбранное действие. Выбор сохраняется после перезапуска, при переключении проектов и при переходе между FLTK и Nana.

В режиме **Собрать и запустить** после успешной сборки запускается выбранная цель с её параметрами. Отмена или ошибка отменяет последующий запуск. Если цель ещё не выбрана и собран один EXE, он выбирается автоматически; при нескольких EXE панель предлагает выбрать цель. Если выбранный EXE отсутствует, запуск пропускается с объяснением в журнале.

Во время обычной сборки и пересборки основная кнопка **Запустить** доступна до постановки запуска в очередь. Нажатие кнопки или **Ctrl+F5** планирует запуск после успешной сборки; кнопка становится недоступной с подписью **Ожидание**. Такое же состояние показывается при команде **Собрать и запустить**. Это работает и при первой сборке, когда EXE ещё нет. В строке состояния появляется **Запуск после сборки**, а подсказка кнопки подтверждает ожидание. Запуск использует сохранённые параметры выбранной цели. Ошибка, отмена и закрытие панели сбрасывают ожидание; подпись возвращается к **Запустить**, а после запроса отмены кнопка недоступна до завершения операции. Отдельные действия **Очистить** и **CMake** запуск не планируют. Геометрия кнопки при смене подписи сохраняется.

Горячие клавиши действуют в окне панели: **F5** — собрать и запустить, **F6** — собрать или отменить текущую сборку, **Ctrl+F5** — запустить или остановить приложение, **Ctrl+O** — выбрать CMakeLists.txt. Меню недавних проектов доступно через **↓** или **F4** на кнопке выбора проекта и её стрелке. Во время работы приложения F5/F6 не начинают новую сборку.

Под кнопками отображается прогресс сборки. Панель распознаёт проценты вида `[ 42%]` и счётчик этапов вида `[12/80]`, в том числе с цветными ANSI-последовательностями. Если генератор не сообщает прогресс (например, MSBuild), во время подготовки и сборки движется индикатор без процентов. Полученные 100% не означают завершение: результат определяется кодом выхода процесса.

Стрелка рядом с кнопкой сборки открывает меню в порядке **Собрать**, **Собрать и запустить**, **Очистить**, **Пересобрать**, **CMake**; меню также доступно через **↓** или **F4** на кнопке сборки. Выбранный режим отмечен в меню. Пункт **Пересобрать** выполняет штатную очистку CMake (`--clean-first`), затем собирает весь проект; сохранённая цель остаётся доступна следующей обычной сборке. Очистка запускает только цель `clean` для уже настроенного каталога сборки, без отдельного запуска конфигурации и последующей компиляции. Пункт **CMake** заново конфигурирует проект с текущими параметрами и обновляет сведения о целях без компиляции, очистки и запуска. Эти три разовых действия сохраняют режим кнопки и не планируют запуск. Исходники, CMakeCache и сохранённые параметры остаются доступны. Эти действия можно отменить той же кнопкой; после завершения отображается длительность, для конфигурирования — **CMake**.

Для повторной сборки панель проверяет принадлежность каталога проекту, данные генератора, наличие подготовленных файлов и соответствие параметрам конфигурации. В подготовленном каталоге поиск Qt и предварительный `cmake -S … -B …` пропускаются, в том числе после перезапуска панели. Изменение цели сборки и обычная пересборка не требуют предварительного CMake. Изменение конфигурации одноконфигурационного генератора или флажка тестов, отсутствующие данные File API и незавершённое конфигурирование требуют подготовки; замена компилятора в существующем каталоге по-прежнему требует другого каталога сборки. При изменении CMakeLists.txt генератор может штатно выполнить CMake внутри `cmake --build`. Для принудительного конфигурирования используйте пункт **CMake**.

По умолчанию панель задаёт `BUILD_TESTING:BOOL=OFF` и `BUILD_TESTS:BOOL=OFF`, в том числе для существующего кэша CMake. Чтобы включить эти тестовые цели, установите флажок **Собирать тесты** в настройках. Выбор сохраняется; панель собирает тесты, но не запускает их. Собственные переключатели тестов проекта задавайте в поле **Параметры CMake**.

В поле **Параметры CMake** под CMake.exe можно указать дополнительные аргументы конфигурирования, например `-DDESIGNER_BUILD_TESTS=OFF -DMY_PATH="C:/Каталог с пробелами"`. Они сохраняются отдельно для каждого проекта, совместимы между FLTK и Nana и передаются непосредственно CMake без командной оболочки. Значения с пробелами заключайте в двойные кавычки; обратный слеш перед закрывающей кавычкой удваивайте либо используйте `/` в пути. Аргументы применяются после стандартных значений панели, поэтому явные `-D` имеют приоритет над флажком тестов. Конфигурация Release/Debug по-прежнему берётся из поля «Конфигурация»; служебные определения генератора, компилятора и путей панели через `-D` не принимаются. Поддерживаются также `-U`, `-C` и параметры диагностики CMake. Проект, каталог сборки, генератор и действие выбирает панель: `-S`, `-B`, `-G`, `-P`, `--build`, `--preset` и другие переключатели режима здесь недопустимы.

Изменение или очистка строки параметров требует конфигурирования при следующей сборке. Пункт **CMake** применяет её сразу без компиляции; повторная сборка с прежними параметрами пропускает отдельную конфигурацию. Удаление `-D` из строки не удаляет уже записанную переменную из кэша CMake: задайте новое значение или используйте `-U ИМЯ_ПЕРЕМЕННОЙ`.

Перед повторной сборкой закройте запущенное приложение проекта и его вспомогательные процессы. Windows не позволяет перезаписывать работающий EXE: при ошибке MSVC `LNK1168` панель покажет подсказку, а имя файла останется в журнале линкера.

Кнопка **Собрать** во время сборки меняется на **Отменить**. При работающем проекте **Запустить** меняется на **Остановить**: остановка завершает процесс и его дочерние процессы. Рабочий каталог запуска по умолчанию — папка выбранного EXE. Стрелка показывает все собранные исполняемые цели проекта и отмечает выбранную; выбор в меню сохраняется без запуска. Если цель ещё не выбрана или её EXE временно отсутствует, основная кнопка открывает этот же список. Если цель ещё не выбиралась и собран единственный EXE, он выбирается автоматически. На кнопке запуска список можно открыть клавишей **↓** или **F4**. Во время сборки и работы приложения стрелка недоступна.

Список EXE определяется через CMake File API и восстанавливается из существующего каталога сборки без запуска CMake. При возвращении к ранее выбранному проекту восстанавливаются все его параметры сборки и цель запуска. Если ответы File API удалены, остаётся доступен сохранённый EXE, пока он существует; полный список обновится после сборки.

Журнал открывается кнопкой-иконкой справа в заголовке и раскрывается под панелью. При открытом журнале окно можно растягивать по вертикали; выбранная высота сохраняется. Если прокрутить журнал вверх, новые строки не меняют позицию просмотра. Автопрокрутка возобновляется, когда вы вручную прокрутите журнал до конца. При ошибке журнал открывается автоматически. Настройки сохраняются в `%LOCALAPPDATA%\CMakeBuild\settings.ini`. Для навигации доступны обычные `Tab` и `Shift+Tab`; `Alt+F4` закрывает окно, `Escape` закрывает настройки.

Если проект требует Qt, панель автоматически ищет установленные Windows-наборы Qt 6 и Qt 5: в каталогах `Qt` на локальных дисках, в пользовательских каталогах и Program Files, по регистрации установщика Windows, переменным `QTDIR`, `QT_ROOT`, `QT_INSTALL_DIR`, `Qt6_ROOT`, `Qt5_ROOT`, путям `CMAKE_PREFIX_PATH` и Qt-инструментам в `PATH`. Проверяются корень установки, каталог версии и каталог набора; полный обход дисков не выполняется.

Для конфигурации CMake панель добавляет совместимые наборы в `CMAKE_PREFIX_PATH` окружения дочернего процесса. Наборы MSVC и MinGW, x64, x86 и ARM64 разделяются; для MinGW учитывается также основная версия GCC. Более новые версии Qt идут первыми, а требуемую версию проверяет сам `find_package`. Это работает и для поиска Qt во вложенных файлах CMake. Android и другие наборы для иных платформ не добавляются.

Уже указанные пути проекта, `Qt6_DIR`/`Qt5_DIR`, кэш CMake и пользовательский `CMAKE_PREFIX_PATH` сохраняют приоритет. В журнале видны автоматически добавленные пути и Qt, выбранный CMake; список установленных наборов также доступен в настройках. Для необычной установки можно задать `QTDIR` либо `CMAKE_PREFIX_PATH` перед запуском панели. Если нужный модуль Qt не установлен, его необходимо установить: автоматического перебора старых версий при отсутствии модуля нет.

Если проект уже собирается в Qt Creator, удобно выбрать его существующий каталог сборки: в `CMakeCache.txt` уже записаны пути к Qt, используемый генератор и другие параметры. При сборке и запуске панель добавляет каталог DLL выбранного Qt в `PATH`, в том числе после перезапуска панели. Другие нестандартные зависимости проекта должны быть доступны в окружении или указаны в его настройках CMake. Приложение не заменяет установку CMake, компилятора и библиотек собираемого проекта.

## Сборка панели

Нужны Windows 10/11, CMake 3.24 или новее и компилятор с поддержкой C++23: Visual Studio 2022 с компонентом «Разработка классических приложений на C++» либо MinGW-w64. Для MinGW нужен `mingw32-make.exe` из того же набора инструментов.

CMake загружает официальный [снимок FLTK 1.5.0-dev](https://github.com/fltk/fltk/tree/b8ccd16eb8cf084abca213ef6be5a407f33cc090), commit `b8ccd16eb8cf084abca213ef6be5a407f33cc090` от 2026-05-30, и проверяет SHA256 архива `e4660e4b58e835eed27ab0a2af48278d53af35c191cd492642111030c7502297`. Этот снимок содержит исправления [Windows DPI #1439](https://github.com/fltk/fltk/issues/1439): согласованную смену масштаба окна и содержимого, сохранение логического размера и положения курсора при переносе безрамочного окна между мониторами. В FLTK 1.4.5 и ветке `branch-1.4` этих исправлений нет. Это версия разработки, закреплённая точным commit; плавающие ветки и установленная в системе FLTK не используются. Исходники и сборка зависимости находятся в `_deps` внутри существующего каталога сборки.

Для первой конфигурации нужен доступ к GitHub либо заранее распакованная локальная копия этого снимка FLTK. Повторная конфигурация использует скачанные исходники. Для сборки без загрузки из сети укажите локальные исходники:

```powershell
.\build.ps1 -Toolchain MSVC -Configuration Release -FltkSourcePath 'C:\Dependencies\fltk-b8ccd16eb8cf084abca213ef6be5a407f33cc090'

# Та же настройка при непосредственном вызове CMake.
cmake --preset msvc -DCMAKEBUILD_FLTK_SOURCE_DIR=C:/Dependencies/fltk-b8ccd16eb8cf084abca213ef6be5a407f33cc090
```

Путь сохраняется в кэше соответствующего пресета. CMake проверяет версию исходников и контрольную сумму драйвера Windows с исправлениями DPI. Прежний локальный каталог 1.4.5 нужно заменить этим снимком либо очистить `CMAKEBUILD_FLTK_SOURCE_DIR`, чтобы CMake скачал зависимость. Собирается только статическая основная библиотека `fltk::fltk`; OpenGL, FLUID, библиотека forms, Cairo, SVG, поддержка планшета, примеры, тесты и документация зависимости отключены. Библиотеки изображений и кодеков не входят в сборку панели.

Рекомендуемый способ из PowerShell:

```powershell
cd C:\GitRepos\CmakeBuild
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

Скрипт ищет CMake в `PATH` и обычных каталогах установки CMake, Qt Tools и Visual Studio. При наличии Visual Studio 2022 выбирается MSVC. Дополнительные варианты:

```powershell
# MSVC, Release; сразу открыть готовую панель.
.\build.ps1 -Toolchain MSVC -Configuration Release -Run

# MinGW; путь до каталога bin можно указать явно.
.\build.ps1 -Toolchain MinGW -MinGWPath C:\Qt\Tools\mingw1310_64\bin

# Если CMake установлен в другом каталоге.
.\build.ps1 -CMakePath 'C:\Tools\CMake\bin\cmake.exe'
```

Готовый результат **всегда** находится в `C:\GitRepos\CmakeBuild\CMakeBuild.exe`, независимо от компилятора и конфигурации. Следующая успешная сборка обновляет этот файл. При переносе исходников готовый EXE находится в корне новой папки проекта.

Промежуточные файлы остаются в постоянных каталогах `build\msvc`, `build\mingw-release` и `build\mingw-debug`. Внутренние EXE разных конфигураций разделены, затем цель `CMakeBuildPublish` обновляет корневой файл, в том числе при повторной сборке без изменений. Сборки панели выполняйте последовательно.

Можно использовать CMake напрямую, если он добавлен в `PATH`:

```powershell
cmake --preset msvc
cmake --build --preset msvc-release --parallel
```

Для MinGW сначала добавьте его `bin` в `PATH`, затем используйте пресет `mingw-release` и для конфигурации, и для сборки.

Если нужно явно указать цель, используйте `cmake --build --preset msvc-release --target CMakeBuildPublish --parallel`: эта цель гарантирует обновление корневого EXE даже при переключении на ранее собранную конфигурацию.

## Поставка

FLTK статически включена в EXE. MSVC собирает панель и FLTK с одинаковой статической средой выполнения `/MT` (`/MTd` в Debug). MinGW использует статические библиотеки C++ и потоков. Внешние FLTK, Qt и runtime DLL для панели не требуются. Зависимости от системных DLL Windows остаются штатными.

Манифест с PerMonitorV2 DPI и поддержкой длинных путей встроен в EXE. Масштабированием виджетов управляет FLTK. Собственная точка входа `wWinMain` обеспечивает GUI-приложение без консольного окна в Release и Debug.

Для распространения панели предназначена сборка **Release**. Для запуска проектов с Qt или другими внешними библиотеками требуются установленные зависимости этих проектов; окружение DLL для выбранного Qt панель восстанавливает из кэша CMake.

CMakeBuild основан в том числе на работе [проекта FLTK](https://www.fltk.org). Исключения в лицензии FLTK разрешают статическую поставку приложения одним EXE.

Проверены отмена конфигурации CMake, остановка приложения и его дочернего процесса, закрытие во время запуска и конфигурации, завершение дерева процессов и ожидание движка без зависания.

Для журнала проверены большая нагрузка, ограничение роста, Unicode-обрезание, выделение, вертикальная и горизонтальная прокрутка, автопрокрутка, перенос строк и изменение высоты. Переключение светлой/тёмной палитры сохраняет виджеты, шрифты, фокус, геометрию, ввод и выделение в настройках. Тесты работают с отдельными временными INI; пользовательские настройки не подменяются тестовым проектом.

Главное окно и настройки проверены в светлой и тёмной теме через фактическую отрисовку FLTK в `Fl_Image_Surface`. Регрессионная проверка частичной перерисовки подтверждает изменение нажатой кнопки и поля ввода при сохранении всех пикселей остальных элементов.

Повторная проверка нативного окна через инструмент управления окнами ограничена ошибкой активации. Проверки на реальных дисплеях 100/125/150/200% и нескольких мониторах отдельно не выполнялись. MinGW-сборка и её системные импорты подтверждены; отдельный изолированный запуск MinGW остался непроверенным.
